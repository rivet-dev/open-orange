# Bindings

OpenOrange reads your bindings from the same `wrangler.jsonc` as `wrangler dev`.
Each binding runs as is, needs a service that you set, or is not supported, in
which case it loads and its calls throw.

## Quickstart

You need the `orange` CLI.

<Steps>

<Step title="Add the bindings">

Use the same keys as on Cloudflare.

```jsonc
{
  "name": "my-worker",
  "main": "src/index.ts",
  "compatibility_date": "2026-09-03",
  "kv_namespaces": [{ "binding": "CACHE", "id": "cache" }],
  "ai": { "binding": "AI" },
  "images": { "binding": "IMAGES" }
}
```

</Step>

<Step title="Check them">

`orange doctor` lists each binding, what it runs on, and what it needs from
you.

```sh
$ orange doctor
  Binding      Resource       On Rivet          Runs on
! env.IMAGES   Images         not supported     stub · calls throw
               Orange has no backend for this binding. Call the service's HTTP API with fetch(), or
               keep this code off Orange.
               https://github.com/rivet-dev/open-orange/blob/main/docs/modules/bindings.mdx
  env.AI       Workers AI     needs a service   OpenAI-compatible API
               Set OPENROUTER_API_KEY, or ORANGE_AI_BASE_URL for another provider.
               https://github.com/rivet-dev/open-orange/blob/main/docs/modules/workers-ai.mdx
  env.CACHE    KV Namespace   runs as is        Rivet Actor
               https://github.com/rivet-dev/open-orange/blob/main/docs/modules/kv.mdx

  1 of 3 bindings run as is, 1 needs a service, 1 is not supported
```

</Step>

<Step title="Set up each service">

Put the variable that `orange doctor` names in `.dev.vars`, next to
`wrangler.jsonc`, and check again.

```sh
$ echo 'OPENROUTER_API_KEY=<your key>' >> .dev.vars
$ orange doctor
✓ Workers AI    env.AI · OpenRouter

● Ready for orange dev
```

</Step>

<Step title="Start the Worker">

When it starts, `orange dev` lists each binding and what it runs on.

```sh
$ orange dev
```

</Step>

</Steps>

## Replace a binding that is not supported

The Worker still starts, and only the calls to that binding throw. Move those
calls to a service that the Worker reaches with `fetch()`. The reference below
names one for [Vectorize](#vectorize), [Images](#images), and
[Analytics Engine](#analytics-engine).

## Set the variables on a deploy

`orange deploy` keeps `.dev.vars` out of the image. Pass it as secrets
instead. See [Variables and secrets](../deploy#variables-and-secrets).

```sh
$ orange deploy --secrets-file .dev.vars
```

#### Compatibility

| Binding | Wrangler key | Kind | Runs on | Notes |
| --- | --- | --- | --- | --- |
| Variables | `vars` | Runs as is | The Worker process | Strings and JSON values. |
| Local secrets | `.dev.vars`, `.env` | Runs as is | The Worker process | Loaded like `wrangler dev`. See [Variables and secrets](#variables-and-secrets). |
| Secrets Store | `secrets_store_secrets` | Runs as is | The Worker process | Local values come from `.dev.vars` or the process environment. See [Secrets Store](./secrets-store). |
| Version metadata | `version_metadata` | Runs as is | The Worker process | See [Version metadata](./version-metadata). |
| `unsafe_eval` | `unsafe.bindings` | Runs as is | The Worker process | |
| Static assets | `assets` | Runs as is | Local files | See [Static assets](./assets). |
| Durable Objects | `durable_objects` | Runs as is | One Rivet Actor for each object | Partial. Same-Worker classes from `new_sqlite_classes` and `new_classes` migrations. See [Durable Objects](./durable-objects). |
| Durable Objects from another Worker | `durable_objects` with `script_name` | Runs as is | The other Worker's Rivet Actors | Both Workers run in one `orange dev`. See [Multiple Workers](./multi-worker). |
| Service bindings to this Worker | `services` | Runs as is | The Worker process | `fetch()`, JS RPC, named entrypoints, `props`, and `ctx.exports`. |
| Service bindings to another Worker | `services` | Runs as is | The other Worker's process | Partial. Run both Workers in one `orange dev` with repeated `-c`. WebSocket upgrades throw. See [Multiple Workers](./multi-worker). |
| Dispatch namespaces | `dispatch_namespaces` | Runs as is | The Workers of the `orange dev` session | Partial. See [Multiple Workers](./multi-worker). |
| KV | `kv_namespaces` | Runs as is | One Rivet Actor for each namespace | See [KV](./kv). |
| D1 | `d1_databases` | Runs as is | One Rivet Actor for each database | See [D1](./d1). |
| Rate Limiting | `ratelimits`, `unsafe.bindings` | Runs as is | One Rivet Actor for each namespace | See [Rate Limiting](./rate-limiting). |
| R2 | `r2_buckets` | Runs as is | One Rivet Actor for each bucket, or your S3-compatible store | Set `ORANGE_R2_<BUCKET>_S3_*` to use Amazon S3, Cloudflare R2, Google Cloud Storage, Backblaze B2, or Neon Object Storage. See [R2](./r2). |
| Queues | `queues.producers`, `queues.consumers` | Runs as is | One Rivet Actor for each queue | See [Queues](./queues). |
| Workflows | `workflows` | Runs as is | Cloudflare's own Workflows engine, with one Rivet Actor for each instance | Partial. See [Workflows](./workflows). |
| Tail Workers | `tail_consumers` | Runs as is | Rivet Durable Streams | Partial. See [Tail Workers](./tail-workers). |
| Worker Loader | `worker_loaders` | Runs as is | One Node.js process for each dynamic Worker, in an agentOS VM | Partial. See [Worker Loader](./worker-loader). |
| Workers AI | `ai` | Needs a service | An OpenAI-compatible provider | Set `OPENROUTER_API_KEY`, or `ORANGE_AI_BASE_URL` for OpenAI, Groq, Together AI, or Fireworks AI. See [Workers AI](./workers-ai). |
| Send Email | `send_email` | Needs a service | Your SMTP server | Set `ORANGE_EMAIL_SMTP_URL` to Amazon SES, Resend, Postmark, SendGrid, or Mailgun. Without it, the binding throws. See [Email](./email). |
| Browser Rendering | `browser` | Needs a service | A hosted browser or your Chrome, through its DevTools Protocol endpoint | Set `ORANGE_BROWSER_CDP_URL` to Browserbase, Browserless, or Steel. Without it, the binding throws. See [Browser Rendering](./browser-rendering). |
| Hyperdrive | `hyperdrive` | Needs a service | Your database, with a direct connection | Set the local connection string, as for `wrangler dev`, such as PlanetScale, Amazon RDS, Neon, or Supabase. No pooling or query cache. See [Hyperdrive](./hyperdrive). |
| Analytics Engine | `analytics_engine_datasets` | Not supported | Nothing | See [Analytics Engine](#analytics-engine). |
| Vectorize | `vectorize` | Not supported | Nothing | See [Vectorize](#vectorize). |
| Images, Media, Stream | `images`, `media`, `stream` | Not supported | Nothing | See [Images](#images). |
| Pipelines | `pipelines` | Not supported | Nothing | See [Pipelines](#pipelines). |
| AI Search | `ai_search`, `ai_search_namespaces` | Not supported | Nothing | See [AI Search](#ai-search). |
| mTLS certificates | `mtls_certificates` | Not supported | Nothing | See [mTLS certificates](#mtls-certificates). |
| VPC | `vpc_networks`, `vpc_services` | Not supported | Nothing | See [VPC](#vpc). |
| Legacy blobs | `text_blobs`, `data_blobs`, `wasm_modules` | Not supported | Nothing | See [Legacy blobs](#legacy-blobs). |
| Other binding types | | Not supported | Nothing | Includes other `unsafe` binding types. |

#### Kinds

- **Runs as is:** OpenOrange implements the Cloudflare API. You set nothing.
- **Needs a service:** OpenOrange implements the Cloudflare API on a service
  that you supply, such as your SMTP server. You set one variable that points
  to it.
- **Not supported:** Orange has no backend for the binding. The Worker loads,
  and `env.NAME` exists. Each method call throws an error that names the
  binding and suggests an alternative. [Analytics Engine](#analytics-engine)
  is the exception: it accepts writes and drops them.

`orange doctor` reports each binding of your project as one of these kinds. It
does not list variables (`vars`, `.dev.vars`, and `.env`), because they need
nothing on Rivet. A binding that is not supported does not fail
`orange doctor`, also with `--strict`.

#### Where the data goes

- Under `orange dev`, Rivet Actors run on a local Rivet Engine, and the data
  stays on your machine.
- Under `orange deploy`, they run on your Rivet cluster.
- A binding that needs a service sends its data to the service that you set.

#### Configuration that stops `orange dev`

Configuration that changes how the Worker runs, not what `env` contains, stops
`orange dev` with `Unsupported Wrangler configuration: <keys>`. The keys are
`cloudchamber`, `connect`, `define`, `exports`, `legacy_assets`,
`pages_build_output_dir`, `site`, `streaming_tail_consumers`,
`triggers.events`, and any `unsafe` setting other than `unsafe.bindings`.

These load instead:

- `orange dev` accepts `containers` with a warning, and runs
  `@cloudflare/sandbox` classes on a sandbox provider, such as E2B, Daytona,
  or Freestyle. See [Sandbox](./sandbox).
- `orange dev` runs `triggers.crons` (see [Cron Triggers](./cron-triggers)),
  and delivers `queues.consumers` to the Worker's `queue()` handler (see
  [Queues](./queues)).

#### Stubs

`orange dev` marks each binding that is not supported in its binding table at
startup, with what to use instead on the next line:

```text
  Binding        Resource            Runs on
! env.IMAGES     Images              stub · calls throw
                                     See the OpenOrange bindings documentation for supported bindings.
```

The binding is a stub, and it is safe to pass around. `typeof env.IMAGES` is
`"object"`, reading a property returns a function, and awaiting the stub does
not call it. Calling any method throws an `Error` with the same message:

```js
await env.IMAGES.info(stream);
// Error: Images binding "IMAGES" is not supported by OpenOrange. See the OpenOrange bindings documentation for supported bindings.
```

The message's second sentence is the alternative for that binding type, such
as a vector database for Vectorize, or an import for a Wasm module.
`orange doctor` prints its own hint for each stub, with a link to this page.

#### Variables and secrets

`orange dev` resolves variables with Wrangler's own `wrangler dev` logic:

1. It starts with `vars` from the Wrangler configuration.
2. It loads `.dev.vars.<env>` or `.dev.vars` next to the configuration file.
3. If neither file exists, it loads `.env`, `.env.local`, `.env.<env>`, and
   `.env.<env>.local`. Set `CLOUDFLARE_INCLUDE_PROCESS_ENV=true` to also load
   the process environment.
4. Loaded values become string bindings that replace `vars` with the same name.
5. If `secrets.required` is set, only the listed keys load, and `orange dev`
   warns about missing keys with
   `Missing required secrets: <keys>. Add them to .dev.vars, .env, or set as environment variables.`

- A `.dev.vars` entry named after another binding, such as a Secrets Store
  binding, stays that binding's local value and does not replace it.
- Secret values never become part of the version metadata ID.

#### Bindings without a page

Orange has no backend for these bindings. Each card's status, migration path,
and checks come from the conformance data.

##### Vectorize

<BindingStatus
  binding="vectorize"
  works="The configuration loads, and `env.NAME` is a stub that the Worker can pass around"
  missing="Every method. Each call throws, and the error names a vector database to use instead."
/>

The error's alternative reads: `Call a vector database, such as Qdrant Cloud
or Pinecone, with fetch(), or use pgvector through Hyperdrive. For a few
thousand vectors, store the embeddings in SQLite and rank them by cosine
similarity in JavaScript.`

| Use instead | How the Worker reaches it |
| --- | --- |
| [pgvector](https://github.com/pgvector/pgvector) on [Neon](https://neon.com/docs/extensions/pgvector) or [Supabase](https://supabase.com/docs/guides/database/extensions/pgvector) | A [Hyperdrive](./hyperdrive) binding and a Postgres driver |
| [Qdrant Cloud](https://qdrant.tech/documentation/cloud/authentication/) | `fetch()` to `https://<cluster host>:6333`, with the `api-key` header |
| [Pinecone](https://docs.pinecone.io/guides/get-started/quickstart) | `fetch()` to the index host, with the `Api-Key` header |
| SQLite in a [Durable Object](./durable-objects), for a few thousand vectors | Store the embeddings, and rank them by cosine similarity in JavaScript |
